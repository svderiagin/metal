Где редактировать и повторять импорт:

- `data/imported-catalog.json` — единственный сгенерированный набор для интерфейса: категории, семейства, характеристики, описания и рассчитанные цены. Его можно читать и редактировать, но повторный импорт пересоздаёт этот файл.
- `imports/overrides.json` — устойчивые ручные изменения. `categories` и `families` индексируются локальным ID и принимают описания/названия; `products` индексируется исходным ID и принимает ручные поля варианта. `matches` сопоставляет исходный ID с существующим локальным ID. Согласованные исключения исходных ID перечислены в `excludedSourceIds`.
- `excludedSourceIds` в overrides закрепляет явно согласованные удаления: ключ — исходный ID, поля — `reason` и `replacementProductId`. Импорт пропускает запись, сохраняя все исходные предложения в манифесте со статусом `excluded`; это не автоматическое признание одинаковых профилей дублями. Старые товарные URL перенаправляются правилами `next.config.ts`.
- `sourcePrices` в overrides позволяет владельцу явно задать новую **исходную** сумму для исходного ID, например `"80044": "77500.00"`. После неё всё равно применяется ×0.90; исходная сумма снимка остаётся в манифесте отдельно. Не задавайте уже уменьшенную цену в `products.price` — проверка согласованности цены должна выявлять такое расхождение.
- `scripts/import-catalog.mjs` — явные правила категорий, семейства и исходные русские описания. `scripts/pricing.mjs` — дробь `90n / 100n` и разбор цены. Никакой скидки повторно от сгенерированной цены нет.
- Прежние вручную поддерживаемые товары остаются в `data/products/*.ts`. Прежние категории/семейства — в массивах `originalCategories`/`originalSubcategories`; импорт заново читает их и сохраняет дополнения владельца. `imports/baseline.json` хранит исходное состояние до этой работы для проверки и резервного сопоставления.
