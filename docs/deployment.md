# Запуск приложения

Сохранён существующий Node-процесс Next.js: `npm run build` → `npm run start`.
Статический экспорт не включён: маршрутам `/api/*` и оптимизатору изображений нужен сервер.
Новых сервисов, зависимостей и настроек хостинга аудит не добавляет.

Для DigitalOcean App Platform используйте тип Web Service, корень этого репозитория,
build command `npm run build`, run command `npm run start` и Node.js 22.x из `package.json`.
`next start` принимает порт из `PORT`; он должен совпадать с HTTP-портом, заданным для сервиса.
Стандартный hostname Next.js — `0.0.0.0`. Для локальной проверки допустим явный `--hostname 127.0.0.1`.
Проверка HTTP-доступности может обращаться к `/`.

В репозитории нет `.do/app.yaml`, Dockerfile или отдельной конфигурации App Platform.
Существующие настройки удалённого приложения не проверялись и не менялись.
В сборку должны входить папка `public`, локальные `data` и файлы приложения;
скачанное зеркало поставщика не требуется для сборки и запуска.

Сборка обновляет только хеши публичных изображений командой `prebuild`.
Она не запускает импорт каталога и не пересчитывает скидку.
Секреты не должны иметь префикс `NEXT_PUBLIC_`.

Публичные страницы работают. Отправка заявок, постоянное хранение заказов и онлайн-оплата не подключены:
без реализации доставки и платёжного провайдера соответствующие API возвращают ошибку,
а не подтверждают доставку или оплату. Эти ограничения существовали до аудита;
заполнения `.env` без реализации интеграции недостаточно.

Локальная production-проверка:

```sh
npm test
npm run lint
npm run build
npm run start -- --hostname 127.0.0.1 --port 3100
node scripts/check-local-browser.mjs
```

Последняя команда требует Chrome с CDP на `127.0.0.1:9224`. Другие адреса задаются через `AUDIT_URL` и `AUDIT_CDP`.
Проверки открывают отдельную вкладку, подменяют отправку форм в браузере и сохраняют результаты в `.tmp/local-audit/`.
Не запускайте их для публичного сервиса: предназначены для локального тестового экземпляра.
