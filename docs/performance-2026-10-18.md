В категориях без главной фотографии preload отсутствует. Оптимизации карусели из `docs/image-performance.md` сохранены.

## Условия и ограничения измерений

Две отдельные копии production-сборок, Next.js 16.2.11, React 19.2.4, Node 25.9.0, отдельный headless Chrome 155. Desktop 1440×1000/DPR 1, mobile 390×844/DPR 2; CPU ×4, канал 200 000 байт/с, задержка 150 мс, окно 8 секунд. Холодный прогон очищал браузерный HTTP-кэш и кэш оптимизатора только временной копии. Затем прогрев и тёплый прогон. На каждой странице по одному холодному и тёплому измерению: это лабораторные наблюдения, не статистически устойчивые медианы и не полевые Web Vitals. Малые различия FCP/LCP не объявляются доказанным ускорением.

Сравнение форматов HTTP отдельно повторено трижды на формат/изображение; там приведены медианы. Desktop LCP на главной в восьмисекундном окне может учитывать смену слайда; первый показ фотографии измерен отдельно. Прочерк означает, что фото не показано в окне наблюдения (часто ниже первого экрана), а не нулевое время загрузки.

Публичная production-среда, CDN, нагрузка и диск сервера не измерялись. Проверка на предписанном `engines.node=22.x` не выполнялась: локальный runtime — Node 25.9.0. Показатели корзины относятся к пустой корзине; функциональная проверка с товаром выполнена отдельно.

## Повторение и хостинг

Основной инструмент — `scripts/measure-images.mjs`; подробная настройка отдельного Chrome/CDP описана в `docs/image-performance.md`. Для этих прогонов задавались `PERF_RUNS=1`, семь маршрутов через `PERF_PAGES`, `PERF_URL` отдельной production-копии, `PERF_LABEL=targeted-before/targeted-after`, `PERF_COLD_IMAGE_CACHE=.tmp/perf-targeted/{before,after}-app/.next/cache/images`, `AUDIT_CDP=http://127.0.0.1:9232`. WebP проверяется тем же инструментом с `PERF_PROFILE=desktop PERF_IMAGE_ACCEPT=image/webp`. Рабочий кэш приложения не очищался.

Исходные сетевые события, Element Timing, размеры картинок и screenshots: `.tmp/image-performance/targeted-{before,after,webp}/`; HTTP-замеры форматов, размеры bundles и диагностический рендер: `.tmp/perf-targeted/`. Компактные числовые результаты сохранены рядом с отчётом в `performance-2026-10-18.json`.

Деплой и production-инфраструктура не менялись. На хостинге следует отдельно проверить достаточность CPU для холодного преобразования, сохранение/эффективность кэша изображений, передачу Accept к Next.js и учёт Vary: Accept в CDN. Задержка региона, очередь CPU, холодный диск и CDN не устраняются достоверно локальным изменением исходников. Настройки хостинга без данных об окружении не назначались.
