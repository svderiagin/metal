# Проверки и регрессия

Источник правил предметной области — навыки каталога, заказов и интерфейса.
Общий маршрут разработки: [development-workflow.md](development-workflow.md).

## Уровни покрытия

- Модульные проверки: расчёты и единицы металлопроката, чистые операции корзины,
  фильтрация, публичные overlays, схемы запросов и подтверждений.
- Проверки API: корректный запрос, повреждённый JSON, превышение размера,
  отсутствие согласия, дубли товаров, отказ адаптера и успешный ответ с локальной подменой доставки.
- Браузерные проверки: поиск и ссылки на варианты, фильтры и сброс,
  добавление/изменение/восстановление корзины, оформление и ошибки сервера,
  просмотрщик изображений, клавиатура и мобильная навигация.
- Скриншоты: главная и каталог, товарные таблицы и мобильные карточки,
  обе темы, окно изображения, корзина и checkout. Хранить эталоны в репозитории,
  отчёты и диффы — в игнорируемых каталогах.

## Правила эталонов

Эталоны зависят от версии браузера и платформы. Среда запуска должна совпадать
с указанной в конфигурации; изменение платформы требует отдельного набора эталонов.
Перед снимком дождаться гидратации, шрифтов и декодирования видимых изображений;
отключить анимацию через reduced motion и штатные настройки тестового браузера.
Не маскировать данные, отступы, кнопки и изображения, которые тест призван защищать.

Создание эталона и сравнение — разные действия. Новые эталоны проверяются глазами,
после чего тот же набор запускается повторно без обновления. Для проверки чувствительности
сравнения использовать временное обратимое изменение и убедиться, что тест его обнаружил.

Реальные уведомления и оплата не участвуют в локальных тестах. Состояния успеха
подменяются на границе API; отдельные API-тесты проверяют, что ненастроенный
адаптер возвращает 503. Широкие проверки данных не должны запускать импорт поставщика
или переписывать его evidence и защищённые snapshots.

## Запуск

Используйте Node 22 (`.nvmrc`) и `npm ci`. Текущая проверенная версия — 22.23.4.
Установите изолированный Chromium командой `npm run test:install` один раз после
установки/обновления Playwright. В Linux нужны системные зависимости:
`npx playwright install --with-deps chromium`.

| Команда | Назначение |
| --- | --- |
| `npm run test:unit` | Старые предметные тесты и новые прямые TypeScript unit/API тесты; без генерирующего pretest |
| `npm run test:coverage` | Новые unit/API тесты с покрытием загруженных `lib/**/*.ts`; минимумы: строки 90%, ветви 85%, функции 85% |
| `npm run lint` | ESLint; архив подготовки изображений `output/` не является кодом приложения |
| `npx tsc --noEmit --incremental false` | Проверка типов без записи кэша |
| `npm run test:build` | Production webpack-сборка в `.next-test`, отдельно от рабочего `.next` |
| `npm run test:e2e` | Функциональные сценарии во всех четырёх проектах браузера |
| `npm run test:visual` | Сравнить скриншоты с сохранёнными PNG, ничего не обновлять |
| `npm run test:visual:update -- --grep 'название теста'` | Осознанно обновить выбранные эталоны после просмотра diff |
| `npm run test:visual:probe` | Отрицательный контроль: временно изменить отступ колонки в браузере и доказать обнаружение screenshot diff |
| `npx playwright show-report` | Последний HTML-отчёт; при сбое доступны screenshot и trace |

После изменения приложения сначала пересоберите `.next-test`. Для изменения
только тестов повторная сборка не нужна. Playwright сам поднимает/останавливает
локальный сервер 127.0.0.1:3100; браузерные команды запускайте **последовательно**,
так как они используют один порт и каталог отчётов. Работающий сервер на 3100
должен обслуживать именно актуальную тестовую сборку.

Браузерные API-запросы перехвачены локально. Корзина каждой проверки изолирована
от пользовательского браузера. Тесты не отправляют реальные заявки и не платят.
Проверяется отсутствие необработанных ошибок JavaScript.

## Среда скриншотов

Playwright **1.64.1**, Chromium **156.0.8078.4** (revision 1248), macOS **27.0.1**,
arm64. В `tests/visual/baselines/darwin/<project>/` хранится 72 эталонных PNG.
`playwright.config.ts` фиксирует DPR 1, ru-RU, Europe/Moscow, reduced motion:

| Проекты | Экран |
| --- | --- |
| desktop-light / desktop-dark | 1440 × 1000 |
| mobile-light / mobile-dark | 390 × 844, touch |

Проверяются девять семейств: швеллер, уголок, квадрат, арматура, балка, профильная
и ВГП труба, профнастил, сетка. Отдельные снимки защищают главную, каталог,
корзину, checkout и округлое окно фото в режиме fit и 1:1. Снимки таблиц ограничены
областью результатов; полный первый экран проверяется на главной и в каталоге.
Отдельный первый экран «Арматуры» защищает крупное титульное фото и введение.
Отдельный снимок `cover-viewer.png` защищает просмотр титульного фото поверх страницы.
Снимок `annotated-profile-viewer.png` проверяет разметку профильной трубы в окне просмотра. Сценарий также сверяет адрес чистой миниатюры.
Дополнительный функциональный сценарий окна использует 320 px и landscape 844×390.

Шрифты и версии ОС могут влиять на растр. Linux/Windows требуют собственного
проверенного набора, а не копирования macOS PNG. Не создавать или обновлять
эталоны автоматически при обычном сравнении. Утверждённые PNG включать в коммит;
`test-results/` и `playwright-report/` содержат временные артефакты и игнорируются.
Probe не меняет код приложения и эталоны; его ожидаемый внутренний screenshot-сбой
считается успехом только при наличии конкретного `*-diff.png`.

## Автоматизация и границы

`.github/workflows/quality.yml` подготавливает Node 22, запускает lint, TypeScript,
unit/API, пороги покрытия, полный аудит зависимостей (включая dev), production-сборку и E2E
на Linux. Отчёты браузера сохраняются 14 дней. Workflow подготовлен по
[официальному руководству Playwright](https://playwright.dev/docs/ci-intro);
удалённый запуск не выполнялся в рамках локального аудита.
Визуальные сравнения запускаются отдельно в документированной macOS-среде;
Linux-эталоны не генерируются без визуального рассмотрения.

После проверки типографики изображений 04.11.2026: unit/API — 177 пройдено из 180,
включая 7 проверок совместимости minimatch/ESLint и 5 проверок изображений/типа
уголка, добавленных после исправления зависимостей; 3 осознанных skip
(один повторный импорт требует opt-in, двум нужны отсутствующие supplier evidence).
Покрытие загруженного ядра: **93,07% строк / 89,30% ветвей / 88,45% функций**.
Это не процент покрытия всего приложения: JSX дополнительно проверяется браузерными
и визуальными сценариями, остальные исторические тесты не включены в этот счётчик.
E2E — **86 пройдено, 2 skip** для mobile-only сценария в desktop-проектах.
После обновления типографики добавлены 12 сценариев (3 × 4 проекта): локальная
загрузка шрифта и размер полей, отказ WOFF2, увеличение текста до 200% вместе
с пользовательскими интервалами. После этого добавлены 36 проверок титульного
фото (9 семейств × 4 проекта): фото занимает доступную ширину, фильтры остаются
справа и не выходят ниже границы левого каталога. Текущий E2E:
**158 пройдено, 2 skip**: дополнительно 24 проверки просмотра титульных фото
(6 сценариев × 4 проекта): четыре варианта подключения, закрытие/фокус,
масштаб/перемещение/адаптивность, ошибка загрузки оригинала.
Unit/API после добавления галереи: **180 пройдено из 183**, прежние 3 skip.
Визуальный набор: 56 сценариев и 68 PNG; эталоны Inter сравниваются повторно
без обновления после визуального просмотра.
Результаты сравнений скриншотов и отрицательного контроля записаны в
[аудите](development-audit-2026-11-04.md).

Временный dev-адаптер minimatch и условия его удаления описаны в
[tools/minimatch-legacy/README.md](../tools/minimatch-legacy/README.md).
После изменения overrides проверяйте чистый `npm ci`, `npm ls minimatch minimatch-modern --all`,
полный `npm audit` и `node --test scripts/minimatch-compat.test.mjs`.

`scripts/catalog-image-labels.test.mjs` сравнивает три проверенных растровых фрагмента
подписей производных вариантов при 1:1: швеллер 6,5, уголок 160×100×10 и квадрат 12×12.
PNG хранятся в `tests/visual/label-baselines/`; сравниваются декодированные пиксели
самих файлов, поэтому эти эталоны не зависят от viewport/ОС браузера. При несовпадении
текущий фрагмент сохраняется в `.tmp/catalog-image-qa/`. Обновлять эталон можно после
сравнения с исходником; снимки неизменённого эталонного товара не заменяют этот тест.
Тот же файл отдельно проверяет сохранность фото всех 14 швеллеров вне зон подписей.
