Папка в репозитории: `public/images/hero/`.
Полный путь на этом компьютере: `C:\Users\Sergei\Projects\metal\public\images\hero`.
Четыре фотографии владельца находятся в этой папке и используются на главной странице. Исходные копии из `images/hero/` сохранены; эта папка в корне не является публичной и сама по себе не обслуживается Next.js. Четыре информационные плитки удалены. Тестовые изображения не являются фотографиями владельца и в проекте не сохраняются.

Единственный файл настроек — `data/hero-slides.ts`. Список путей хранится в `HERO_SLIDES`, интервал — в `AUTO_ROTATE_MS`:

```ts
export const AUTO_ROTATE_MS = 2000;

export const HERO_SLIDES: HeroSlide[] = [
  {id: "hero-01", src: "/images/hero/hero-01.avif", desktopPosition: "50% 50%", mobilePosition: "60% 50%"},
  {id: "hero-02", src: "/images/hero/hero-02.avif", desktopPosition: "50% 50%", mobilePosition: "60% 50%"},
  {id: "hero-03", src: "/images/hero/hero-03.avif", desktopPosition: "50% 50%", mobilePosition: "60% 50%"},
  {id: "hero-04", src: "/images/hero/hero-04.avif", desktopPosition: "50% 50%", mobilePosition: "60% 50%"},
];
```

- Для трёх фотографий удалите строку с `id: "hero-04"`. Также отсутствующие файлы автоматически пропускаются.
- Для изменения порядка переставьте строки массива. Сохраняйте уникальные `id`.
- Для JPEG или PNG положите настоящий файл соответствующего формата и измените `src` на его точное имя с фактическим расширением. Поддерживаются `.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`. Простое переименование расширения не конвертирует файл.
- `desktopPosition` задаёт положение кадра на экранах от 640 пикселей; `mobilePosition` — на телефонах. Проценты работают как `object-position`: `50% 50%` — центр, `70% 50%` смещает область кадрирования вправо. Главный объект лучше располагать в средней или правой части снимка: слева находится текст.
- `AUTO_ROTATE_MS = 2000` означает две секунды между автоматическими переходами. Плавное изменение прозрачности длится 600 мс и задаётся в `components/home/HeroCarousel.module.css`. Две секунды — настройка дизайна, а не требование W3C.
- Рекомендуются горизонтальные фотографии около **2400 × 1400 пикселей**, минимум примерно **1920 × 1100**. Желательный размер WebP/JPEG — **200–500 КБ**, ориентировочно до 700 КБ для сложного изображения. Проверьте детализацию после сжатия. PNG подходит, но обычно значительно тяжелее для фотографий. Next.js создаёт адаптивные оптимизированные варианты автоматически.

## Обновление фотографий

В `next.config.ts` включены `images.formats: ["image/avif", "image/webp"]`: Next.js выдаёт AVIF поддерживающим его браузерам и WebP — браузерам, запрашивающим WebP. Исходные фотографии карусели теперь ожидаются в формате AVIF. После изменения `next.config.ts` перезапустите сервер разработки, если он не перезапустился автоматически.

В режиме разработки (`npm run dev`) после добавления файлов обновите страницу. Перезапуск обычно не нужен. Изменения файла настроек подхватываются автоматически.

В production главная страница предварительно формируется при `npm run build`. После добавления, удаления, замены файлов или изменения настроек выполните новую сборку и разместите её вместе с папкой `public` на сервере. Одного обновления браузера для добавления ранее отсутствовавших снимков недостаточно. Сервер автоматически добавляет к URL снимка параметр `v` с хешем его содержимого: замена фотографии с прежним именем обновляет кэш оптимизатора после обновления страницы в разработке или новой сборки в production. Менять имя файла ради кэша не требуется. Не добавляйте слово `public` в браузерные адреса.

## Поведение

Первый доступный снимок загружается сразу с высоким приоритетом. Остальные начинают загружаться после него; если предыдущий запрос завис, через пять секунд начинается следующий. Переход возможен только к уже декодированному изображению. Отсутствующие файлы отсеиваются на сервере, ошибки загрузки пропускаются в браузере. При нуле фотографий остаётся тёмный фон, при одной — статичный снимок без лишних кнопок.

При двух и более доступных фотографиях отображаются только стрелки. Счётчик и кнопки воспроизведения удалены. Фотографии автоматически меняются каждые две секунды. Наведение, фокус внутри блока, скрытая вкладка и уход блока за экран временно останавливают таймер; после возвращения начинается новый двухсекундный отсчёт. Стрелки и свайпы больше не отключают автопоказ навсегда. Настройка уменьшенного движения отключает автоматический запуск и плавные переходы; ручные стрелки остаются доступными.

Декоративные снимки скрыты от экранных дикторов. Заголовок, текст и ссылки существуют в единственном экземпляре. Автоматические переходы не объявляются постоянно.

Рекомендации: [доступные карусели WAI](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/), [управление автоматическим движением](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html), [пример WAI](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/examples/carousel-2-tablist/), [оптимизация LCP](https://web.dev/articles/optimize-lcp).

## Проверка

`node scripts/check-hero-images.mjs` проверяет настоящие фотографии владельца без их изменения: формат AVIF, совпадение исходных и публичных файлов, HTTP-адреса, декодирование, оптимизацию AVIF/WebP, отображение на компьютере и телефоне, стрелки, цикл и реальный двухсекундный таймер. Повреждённый и зависший запросы моделируются только в браузере. Нужны сайт на порту 3000 и Chrome CDP на 9223; для другого адреса сайта задайте `HERO_TEST_URL`. Отчёт и снимки экрана сохраняются в `.tmp/hero/`.

`node scripts/check-hero-browser.mjs` проверяет карусель через Chrome с CDP на порту 9223 и сайт на порту 3000. Создаёт временные цветные изображения без фотографий, проверяет варианты с нулём, одним, тремя и четырьмя файлами и удаляет их в `finally`. Не запускайте при уже добавленных фотографиях владельца: проверка намеренно откажется перезаписывать их.

Команды общих проверок: `npm run search:check`, `npm run catalog:check`, `npm run lint -- --ignore-pattern 'brokinvest.ru/**'`, `npm run build`.

Проверены размеры 1440 и 390 пикселей, все четыре варианта количества изображений, ошибочная загрузка, реальный двухсекундный таймер, отсутствие параллельных таймеров, стрелки и циклический переход, быстрые клики, кнопка запуска при фокусе внутри блока, наведение, уход за экран, уменьшенное движение, touch-свайп и вертикальная прокрутка. Скрытие вкладки проверено моделированием `document.hidden` и `visibilitychange`, без ручного переключения физических вкладок. При переходе по ссылке в каталог таймер удаляется.

После появления главного блока загрузка и переключение фотографий не вызывают сдвигов макета. При первоначальной загрузке страницы отдельно обнаружен сдвиг от общего шаблона `app/loading.tsx`: его низкий заполнитель заменяется полной страницей и сдвигает подвал. Этот общий шаблон оставлен без изменений, поскольку задача ограничена главным блоком. Реальное кадрирование и визуальное качество фотографий можно окончательно проверить только после их получения; цветные тестовые файлы этого не заменяют.
